# Спецификация требований к ПО

## Pomodoro-таймер с аналитикой

Версия 1.0  
Подготовил: И.М. Серков  
Дата: 25.10.2026

## 1. Введение

### 1.1 Назначение документа

Документ определяет бизнес-, пользовательские, функциональные и нефункциональные требования к настольному приложению «Pomodoro-таймер с аналитикой». Он является основанием для согласования объёма первой версии продукта и проверки результата.

### 1.2 Область применения продукта

Продукт предназначен для пользователей, которым требуется организовать фокусированную работу по технике Pomodoro, связывать сессии с задачами и анализировать личную продуктивность. Это локальное desktop-приложение для Windows, реализуемое на C++ с WinAPI.

### 1.3 Термины

* **Помодоро** — завершённая рабочая сессия; по умолчанию 25 минут.
* **Фаза** — работа, короткий перерыв либо длинный перерыв.
* **Активная задача** — задача, которой назначается текущая сессия.

## 2. Обзор продукта

### 2.1 Бизнес-цели

1. Помочь пользователю поддерживать концентрацию за счёт предсказуемого цикла работы и отдыха.
2. Дать пользователю достоверные локальные данные о затраченном времени и завершённых сессиях.
3. Связать фокус-сессии с конкретными задачами, чтобы планирование было осмысленным.

### 2.2 Функции продукта

Приложение отображает таймер, управляет фазами Pomodoro, ведёт список задач, сохраняет историю сессий и строит статистику по дням, неделям и задачам.

### 2.3 Ограничения

* C++17 или новее; нативный интерфейс Windows API.
* Работа без обязательного подключения к сети.
* Локальное хранение в JSON; внешние сервисы не входят в базовую версию.

### 2.4 Пользователи

Основной пользователь — студент или специалист, выполняющий индивидуальные задачи на ПК с Windows и желающий контролировать интервалы концентрации.

### 3.2 Функциональные требования

| ID | Требование | Критерий приёмки |
|---|---|---|
| REQ-FUNC-001 | Система должна запускать, приостанавливать, возобновлять и сбрасывать таймер. | После нажатия кнопки время меняет состояние без потери выбранной задачи. |
| REQ-FUNC-002 | Система должна поддерживать рабочую фазу, короткий и длинный перерыв. | После завершения фазы предлагается следующая фаза цикла. |
| REQ-FUNC-003 | Система должна уведомлять о завершении фазы. | Пользователь видит системное уведомление и слышит звуковой сигнал. |
| REQ-FUNC-004 | Система должна позволять создавать, редактировать, завершать и удалять задачи. | Изменения отражаются в списке задач и сохраняются после перезапуска. |
| REQ-FUNC-005 | Система должна назначать активную задачу текущей сессии, позволять указать для неё плановое число помодоро и отображать прогресс. | Завершённое помодоро учитывается у выбранной задачи; пользователь видит «выполнено / запланировано». |
| REQ-FUNC-006 | Система должна фиксировать завершённые и прерванные сессии в истории; при прерывании должна запрашивать подтверждение и предлагать указать причину. | Запись содержит дату, длительность, фазу, задачу, статус и при наличии причину прерывания. |
| REQ-FUNC-007 | Система должна отображать статистику за день и неделю. | Выводятся число помодоро, время фокуса и выполнение дневной цели. |
| REQ-FUNC-008 | Система должна строить график количества завершённых помодоро по дням. | График корректно меняется при выборе периода. |
| REQ-FUNC-009 | Система должна показывать статистику по задачам. | Таблица содержит задачу, число сессий и время фокуса. |
| REQ-FUNC-010 | Система должна позволять задать длительности фаз и дневную цель. | Новые значения используются при следующем запуске таймера. |
| REQ-FUNC-011 | Система должна экспортировать статистику за выбранный период в CSV. | В CSV включаются дата, задача, статус сессии, число помодоро и время фокуса; файл открывается в Microsoft Excel и LibreOffice Calc. |

### 3.3 Нефункциональные требования

| ID | Требование |
|---|---|
| REQ-PERF-001 | Главное окно должно быть готово к работе не позднее чем через 2 секунды на ПК с Windows 10/11. |
| REQ-REL-001 | Данные истории и задач не должны теряться при штатном перезапуске приложения. |
| REQ-USAB-001 | Основные действия таймера должны быть доступны не более чем за два действия мышью. |
| REQ-PORT-001 | Приложение должно работать в 64-разрядных Windows 10 и Windows 11. |
| REQ-SEC-001 | Данные пользователя должны храниться только локально и не передаваться без явного действия пользователя. |

| Требование | Метод | Артефакт |
|---|---|---|
| REQ-FUNC-001…003 | Демонстрация | Сценарий таймера |

| REQ-FUNC-007…009 | Демонстрация | Окно аналитики |

## 5. Управление изменениями

Изменения требований оформляются отдельным Pull Request в ветку `requirements`. Перед принятием изменения оцениваются его влияние на интерфейс, модель требований, сроки и критерии приёмки.
