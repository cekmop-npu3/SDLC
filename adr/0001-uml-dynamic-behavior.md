# Моделирование динамического поведения Pomodoro-таймера с помощью UML

## Контекст и постановка задачи

Требования Pomodoro-таймера уже зафиксированы в SRS. Перед реализацией необходимо однозначно описать динамическое поведение: кто инициирует сценарии, как выполняется фокус-сессия, какие состояния проходит объект `PomodoroSession` и как компоненты взаимодействуют при завершении рабочего интервала.

Вопрос: какой набор UML-диаграмм покрывает ключевые сценарии базовой версии без избыточной детализации?

Связанные артефакты: `srs/srs.md`, `sdd.md`, `docs/glossary.md`, `docs/supplementary-specs.md`.

## Драйверы решения

* Трассировка к функциональным требованиям SRS.
* Понятность сценариев для разработки и проверки.
* Соответствие согласованной базовой версии: таймер, задачи, журнал, аналитика и CSV-экспорт.
* Минимально достаточный набор UML-моделей.

## Рассмотренные варианты

* Полный набор структурных и поведенческих диаграмм UML.
* Только текстовые сценарии без UML.
* Набор из четырёх поведенческих диаграмм: Use Case, Activity, State и Sequence.

## Итог решения

Выбран набор из четырёх поведенческих диаграмм. Он задаёт границы и актёров, алгоритм фокус-сессии, допустимые состояния сессии и обмен сообщениями при её завершении.

### Последствия

* Хорошо: поведение системы формализовано до кодирования.
* Хорошо: есть явная связь SDD ↔ SRS.
* Нейтрально: структурный дизайн C++20/WinAPI уточняется отдельными документами.
* Отрицательно: при изменении требований необходимо поддерживать исходники PlantUML, схемы Visio и PNG-представления синхронно.

### Подтверждение

Соблюдение решения проверяется наличием четырёх исходников в `assets/uml/`, PNG-представлений в `assets/png/`, описаний в `sdd.md` и согласованностью с `docs/supplementary-specs.md`.

## Плюсы и минусы вариантов

### Полный набор UML-диаграмм

* Хорошо: покрывает почти все точки зрения.
* Плохо: избыточен для объёма лабораторной работы и базовой версии проекта.

### Только текстовые сценарии

* Хорошо: быстро составляются.
* Плохо: хуже показывают взаимодействие компонентов и допустимые переходы состояний.

### Четыре поведенческие диаграммы

* Хорошо: закрывают контекст, алгоритм, состояния и взаимодействие.
* Хорошо: напрямую связаны с требованиями базовой версии.
* Нейтрально: не заменяют структурное описание архитектуры.

## Дополнительная информация

* Use Case задаёт актёров «Пользователь» и «Windows» и функции таймера, задач, журнала, аналитики и экспорта.
* Activity детализирует запуск, паузу, сброс, завершение работы и выбор следующего перерыва.
* State описывает жизненный цикл `PomodoroSession`: готова, выполняется, приостановлена, завершена, прервана и сброшена.
* Sequence показывает обмен сообщениями между WinAPI-интерфейсом, контроллером таймера, журналом, аналитикой и API уведомлений Windows.
